# Feature Specification: 小組即時狀態與回寫

**Feature Branch**: `codex/007`

**Created**: 2026-11-26

**Status**: Draft

**Input**: 教師活動狀態移除版本標籤；學生端持續顯示小組人數及角色；表單回寫格式、空格檢查及預覽逾時重產；同組答案與教師端活動狀態即時同步；成員斷線滿兩分鐘後回收名額並清除原工作階段身分。

## Clarifications

### Session 2026-11-26

- Q: 回寫前，哪些儲存格應視為「空白」？ → A: 去除首尾空白後仍無文字的儲存格視為空白；全形空格、定位字元與換行也算空白。含公式的儲存格一律視為非空白，即使公式結果顯示空白。

## User Scenarios & Testing

### User Story 1 - 查看小組人數與身分 (Priority: P1)

學生加入小組後，可以持續確認目前同組的在線成員數以及自己是組長或組員；教師的活動狀態區不再出現「版本0」、「版本1」、「版本2」等小字。

**Why this priority**: 學生需要辨識隊伍是否已滿及自己的角色，避免對加入結果產生疑惑；教師也需要清楚閱讀活動狀態。

**Independent Test**: 建立小組並依序加入第二名成員，檢查兩名學生各自看到的人數及角色，並檢查教師各活動狀態標籤。

**Acceptance Scenarios**:

1. **Given** 組長剛建立且加入小組，**When** 查看小組畫面，**Then** 顯示在線人數「1/2」及「組長」。
2. **Given** 組員已成功加入且兩位成員均在線，**When** 任一成員查看小組畫面，**Then** 顯示在線人數「2/2（已滿額）」及各自正確的「組長」或「組員」身分。
3. **Given** 一位成員斷線但仍在兩分鐘恢復寬限期內，**When** 另一位在線成員查看小組畫面，**Then** 顯示在線人數「1/2」，且斷線成員的名額仍保留、不得由新成員占用。
4. **Given** 教師查看邀請中、進行中或結束的活動，**When** 顯示各狀態，**Then** 狀態下方不出現版本 0、1、2 標籤。

---

### User Story 2 - 即時掌握小組與作答變化 (Priority: P1)

教師建立或管理活動時，能立即看到新小組、成員增減及每題回答狀態改變。組內任一成員送出答案後，其他組員不需重新整理即可看見已回答狀態及共用答案。

**Why this priority**: 教師需要可信的即時活動全貌；同組成員需要知道答案已送出，避免重複操作或彼此資訊不一致。

**Independent Test**: 先以兩個組員視窗和教師視窗驗證小組建立、加入或離線成員及答案提交會在兩秒內同步；確認短暫斷線立即減少在線人數但保留席位，期滿才釋出；再於既有容量上限（100 組、200 個有效工作階段）下驗證更新仍於兩秒內到達有權查看的在線畫面，且不需重整。

**Acceptance Scenarios**:

1. **Given** 教師已開啟活動畫面，**When** 學生建立新小組，**Then** 新小組立即出現在教師畫面。
2. **Given** 教師已開啟活動畫面，**When** 小組成員加入、離線或名額釋出，**Then** 教師畫面立即顯示更新後的成員數及狀態。
3. **Given** 教師正在查看題目狀態，**When** 任一小組提交答案，**Then** 教師畫面立即顯示該組及該題的回答狀態與答案。
4. **Given** 同組另一位成員尚未看到答案，**When** 組員提交答案成功，**Then** 其他組員畫面立即將該題更新為已回答並在答案空格顯示已送出的答案。
5. **Given** 多名組員或教師同時開啟活動，**When** 發生上述小組、成員或作答狀態變更，**Then** 所有有權查看該資料的畫面在兩秒內呈現一致的最新狀態，且學生不會因此取得其他小組的作答資料。
6. **Given** 活動已達 100 組及 200 個有效工作階段，**When** 小組、成員或答案狀態變更成功提交，**Then** 從提交成功起兩秒內，所有有權查看且已連線的畫面均呈現最新狀態；僅收到或套用伺服器事件不算完成驗收。

### User Story 3 - 安全預覽並回寫學習單 (Priority: P1)

教師確認回寫預覽後，系統先確認所有預定填入的儲存格皆為空白，再依一致格式回寫。預覽五分鐘後過期時，教師可以重新產生預覽後繼續操作。

**Why this priority**: 回寫前確認避免覆蓋既有內容；清楚一致的文字格式方便教師檢查與學生閱讀。

**Independent Test**: 準備全空白目標格及含非空白內容的目標格各一份學習單，並分別測試預覽即時確認、逾五分鐘確認及重新產生預覽。

**Acceptance Scenarios**:

1. **Given** 預定填入的儲存格全為空白，**When** 教師確認回寫，**Then** 每格寫入「小組：{組別名稱}。回答：{答案}。」；例如「小組：蘋果。回答：0。」及「小組：6。回答：中央處理器。」。
2. **Given** 任一預定填入的儲存格已有非空白內容，**When** 教師確認回寫，**Then** 系統拒絕整批回寫並指出非空白儲存格，要求教師清空該格後重新預覽或確認；不得覆蓋任何儲存格。
3. **Given** 教師產生回寫狀態預覽，**When** 在預覽產生後五分鐘內確認且目標儲存格仍符合條件，**Then** 系統依預覽結果進行回寫。
4. **Given** 回寫預覽產生已超過五分鐘，**When** 教師嘗試確認，**Then** 系統提示預覽已過期並提供重新產生預覽的操作；重新產生成功後可繼續，不得以逾期錯誤阻斷流程。
5. **Given** 預覽已過期且教師重新產生，**When** 新預覽顯示當前回寫狀態，**Then** 新預覽具有新的五分鐘有效期並重新檢查目標格。

### User Story 4 - 回收長期離線的成員席位 (Priority: P1)

學生中斷連線後，可在兩分鐘寬限期內恢復原工作階段。滿兩分鐘仍未恢復時，系統使原工作階段失效、清除其身分工作階段並釋出成員席位；該學生之後只能作為新成員加入。組長同樣適用此寬限期，期滿後該小組停止接受新成員。

**Why this priority**: 避免長期離線工作階段占住小組席位，並確保失效工作階段無法繼續以原成員身分回來。

**Independent Test**: 依序測試一般組員與組長短暫斷線、逾時斷線、舊工作階段重新連線及新成員加入資格。

**Acceptance Scenarios**:

1. **Given** 組員斷線未滿兩分鐘，**When** 原工作階段於寬限期內恢復連線，**Then** 恢復原成員身分與席位，席位數不變。
2. **Given** 一般組員斷線滿兩分鐘仍未恢復且組長仍有效，**When** 寬限期到期，**Then** 原工作階段失效並清除；席位立即釋出，原成員只能以新成員身分重新加入，其他新成員可加入空位。
3. **Given** 組長斷線未滿兩分鐘，**When** 組長於寬限期內恢復，**Then** 原組長身分與小組加入資格維持有效。
4. **Given** 組長斷線滿兩分鐘仍未恢復，**When** 寬限期到期，**Then** 原工作階段失效並清除，小組不再接受任何新成員；其他仍有效的組員可繼續使用該組。
5. **Given** 任一已逾期失效的原工作階段嘗試恢復，**When** 系統收到該工作階段的請求，**Then** 拒絕其原身分恢復，要求以新成員流程重新加入；若組長已逾時，則拒絕加入該組。

### Edge Cases

- 成員恰於斷線兩分鐘期限到達時重新連線：以恢復請求是否在期限內被系統接受判定；到期即先使工作階段失效並釋出名額。
- 一般組員斷線逾時後，另一人同時嘗試加入空位：只允許一個新工作階段取得釋出的席位，其餘請求依名額已滿回覆。
- 組長逾時與組員加入同時發生：組長的到期失效先關閉該組新加入資格，該加入請求不得成功。
- 多個目標儲存格中只要一格非空白，即拒絕整批寫入並列出需清空的格子；不可部分寫入。去除首尾空白後仍無文字的儲存格視為空白，全形空格、定位字元與換行皆屬空白；含公式的儲存格一律視為非空白，即使公式結果顯示空白。
- 預覽到期與使用者確認同時發生：逾五分鐘的預覽一律要求重產；新預覽仍須重新檢查儲存格內容。
- 同組兩個畫面收到答案更新或教師收到活動更新的順序不同：最終畫面須呈現同一最新狀態，且不能重複建立小組、答案或名額。

## Requirements

### Functional Requirements

- **FR-001**: 學生加入小組後，畫面 MUST 持續顯示目前在線成員數及小組容量，格式為「1/2」或「2/2（已滿額）」，並顯示當前學生為「組長」或「組員」。非預期離線成員立即不計入在線數，但在兩分鐘恢復寬限期內仍占用席位。
- **FR-002**: 教師活動列表中的邀請中、進行中及結束狀態 MUST 不顯示「版本0」、「版本1」、「版本2」等版本小字。
- **FR-003**: 同組任一有效成員提交答案後，系統 MUST 即時更新該組所有有效成員畫面，顯示已回答狀態及提交答案；此資訊僅可由該組成員及教師查看。
- **FR-004**: 教師開啟活動期間，系統 MUST 即時同步新建小組、在線成員增加或減少，以及各組各題的回答狀態和答案，不得要求教師重新整理頁面。
- **FR-005**: 即時同步的變更 MUST 自狀態變更成功提交後兩秒內，呈現在所有具有相應查看權限的已連線畫面；驗收終點為用戶端畫面已套用最新狀態，而非僅收到伺服器事件。
- **FR-006**: 學習單每筆回寫內容 MUST 採用「小組：{小組顯示名稱}。回答：{答案}。」格式；小組顯示名稱使用資料模型中的 `displayName`，其內容可為小組名稱或代號，並保留答案原有文字內容。例如「小組：蘋果。回答：0。」或「小組：6。回答：中央處理器。」。
- **FR-007**: 執行回寫前，系統 MUST 檢查本次所有預定填入的目標儲存格；去除首尾空白後仍無文字的格子視為空白，全形空格、定位字元及換行均視為空白；含公式的格子一律視為非空白，即使公式結果顯示空白。只有全部目標格為空白時才可寫入。任何目標格有非空白內容時，系統 MUST 拒絕整批回寫、指出需清空的格子，且不得更動任一格。
- **FR-008**: 回寫狀態預覽自產生起五分鐘內有效；超過五分鐘即失效，確認時系統 MUST 提示重新產生預覽並提供可用的重產操作。
- **FR-009**: 重新產生預覽 MUST 重新讀取當前回寫狀態、重新檢查全部目標儲存格，並開始新的五分鐘有效期。
- **FR-010**: 成員非預期離線後兩分鐘內恢復連線時，系統 MUST 恢復原工作階段及角色，不釋出其席位。
- **FR-011**: 成員離線滿兩分鐘仍未恢復時，系統 MUST 使原工作階段失效、清除其成員身分資料並釋出其席位；失效工作階段 MUST NOT 以原成員身分恢復或重新加入，只能經新成員加入流程建立新的身分工作階段。
- **FR-012**: 組長離線滿兩分鐘仍未恢復時，系統 MUST 使原組長工作階段失效並清除其身分；該組 MUST 停止接受新工作階段加入，但仍有效的其他組員 MUST 可繼續使用該組。
- **FR-013**: 組長在兩分鐘內恢復原工作階段時，該組 MUST 保持接受新成員的既有資格；組長逾期失效後，即使原組長以新成員身分重新加入，亦不得重新開放原小組的新成員加入資格。
- **FR-014**: 同時發生的席位釋出、成員加入及組長逾時事件 MUST 產生一致結果；任何席位不得被重複分配，組長逾時關閉小組的事件優先於同期的新成員加入。

### Key Entities

- **小組成員工作階段**: 代表一名當前有效或暫時離線的組員工作階段，包含角色、在線狀態及兩分鐘恢復期限；逾期後不可恢復原身分。
- **小組**: 由組長與組員工作階段構成的團隊，具有兩個席位、加入開放狀態及組內共用的逐題答案。
- **組內答案狀態**: 一組對單題的未回答或已回答狀態；成功提交後包含原始答案並同步給組內成員及教師。
- **回寫預覽**: 教師確認回寫前所見的目標格及寫入內容，包含產生時間、五分鐘有效期限及目標格空白檢查結果。
- **學習單目標儲存格**: 預計接收小組及答案文字的儲存格；執行整批回寫前均須為空白。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 所有已加入小組的學生畫面 100% 顯示正確在線成員數、容量及本人角色；成員上線或離線後兩秒內更新；離線寬限期內席位仍受保留。
- **SC-002**: 教師的三種活動狀態中，版本小字顯示數為零。
- **SC-003**: 有效答案提交後，教師及該組其他在線成員在兩秒內看到一致的回答狀態和答案，無須重新整理。
- **SC-004**: 小組建立、在線成員增減及各題回答狀態的每次變更，教師畫面均在兩秒內更新。
- **SC-005**: 回寫內容 100% 符合「小組：{名稱或代號}。回答：{答案}。」格式，並保留答案文字。
- **SC-006**: 所有目標格空白時可完整回寫；存在一個或多個非空白目標格時，整批寫入次數為零且畫面可辨識所有待清空格。
- **SC-007**: 預覽五分鐘內可確認；逾五分鐘的預覽 100% 被拒絕並可立即重新產生，重產後可正常完成後續回寫。
- **SC-008**: 離線未滿兩分鐘恢復的成員保留原工作階段與席位；離線滿兩分鐘未恢復的原工作階段恢復成功數為零，席位只釋出一次。
- **SC-009**: 組長離線逾兩分鐘後，該小組新成員加入成功數為零；其他仍有效組員可持續查看小組答案。

## Assumptions

- 本功能延伸既有小組活動規則：每組最多兩個工作階段席位，組長占用一席；畫面在線人數只計算目前已連線成員，不推論實際學生人數。斷線成員的席位在兩分鐘寬限期間保留，但不計入在線人數。
- 「離線滿兩分鐘」以系統觀察到連線中斷的時間起算；在兩分鐘界線前成功恢復者保留原身分，期限屆滿仍未恢復者視為工作階段失效。
- 預覽有效期限自成功產生時起算五分鐘。若儲存格在預覽後遭其他操作修改，確認回寫前仍以當下內容執行空白檢查。
- 目標儲存格去除首尾空白後仍無文字時視為空白；全形空格、定位字元及換行均為空白字元。含公式的目標格一律視為非空白，即使公式結果是空字串。任何非空白目標格均導致整批拒絕，避免覆蓋既有內容或只完成部分回寫。
- 兩秒同步目標適用於已連線的教師及有權查看之學生畫面；短暫離線的畫面在恢復連線後須先取得最新狀態。
- 即時更新沿用既有活動容量上限驗收範圍，適用於每場最多 100 組、共 200 個有效工作階段；兩秒目標在此上限下亦成立。
- 教師可查看所有組別作答；學生僅能查看本組答案，延續既有活動的資料可見範圍。
- 組長逾時後原組停止招收新成員，即使組長之後以新成員身分加入亦不重新開放；此行為延續既有組長離開後的規則。
