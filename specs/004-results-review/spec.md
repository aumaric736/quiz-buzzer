# Feature Specification: 課堂搶答結果檢視與檢討

**Feature Branch**: `codex/004-results-review`  
**Created**: 2026-11-20  
**Status**: Draft  
**Input**: User description: 「建立『課堂搶答系統』的子功能：結果檢視與檢討。搶答結束後，學生可以檢視各題的搶答結果；老師可以檢視完整的作答紀錄（題號、組別、答案、送出順位）並進行檢討。邊界情況：搶答尚未結束時學生嘗試檢視、某題無人作答、活動重新開始後舊結果的處理。請依照 constitution 產出組件圖、類別圖與時序圖（.puml 與 PNG）。」

## Clarifications

### Session 2026-11-20

- Q: 老師完整作答紀錄要包含哪些答案？ → A: 記錄搶答期間每組每題第一筆有效提交，包括該題已有勝出者後其他組的有效提交；空白、格式錯誤與同組重複提交不列入。
- Q: 送出順位應如何計算？ → A: 每題各自排序，依系統接收並記錄的先後決定。
- Q: 活動重新開始時舊作答紀錄如何處理？ → A: 同一活動不可重開；另建新活動，保留舊結果並將新舊紀錄分開。
- Q: 建立新活動後，原本參與的學生是否仍要能打開舊活動檢視結果？ → A: 不要；舊結果由老師保留檢視，學生需在切換新活動前查看。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 學生檢視最終結果 (Priority: P1)

搶答結束後，學生可依題號查看各題的搶答結果，包括成功組別、答案，以及無人作答的題目。搶答尚未結束時，學生不能取得任何組別的完整結果。

**Why this priority**: 學生在活動結束後需要確認各題結果，並在進行中維持作答隱私。

**Independent Test**: 以已加入活動的學生查看進行中及已結束活動，確認進行中無結果外洩，結束後各題結果完整且題號一致。

**Acceptance Scenarios**:

1. **Given** 活動仍在搶答進行中，**When** 學生嘗試開啟結果，**Then** 系統顯示尚未結束的明確提示且不回傳結果內容。
2. **Given** 活動已結束且部分題目有人作答，**When** 學生檢視結果，**Then** 系統按題號顯示成功組別及答案。
3. **Given** 活動已結束且某題無人作答，**When** 學生檢視結果，**Then** 該題明確顯示無人作答。
4. **Given** 原活動已結束且老師建立新活動，**When** 老師查看舊活動、學生在切換前查看舊活動，**Then** 舊結果保持不變；學生加入新活動後不能再查看舊結果，且新活動沒有沿用舊紀錄。

---

### User Story 2 - 老師檢視完整作答紀錄並帶領檢討 (Priority: P1)

活動結束後，建立活動的老師可查看作答紀錄，包含題號、組別、答案與送出順位，並使用結果畫面帶領課堂檢討。檢討畫面以檢視為主，不包含新增評分、批改或文字註記。

**Why this priority**: 老師需要掌握各題作答經過與提交順序，才能說明搶答結果。

**Independent Test**: 以建立活動的老師結束有多組作答的活動，檢視紀錄欄位、題目排序、送出順位與無人作答題目；非建立活動老師不得讀取紀錄。

**Acceptance Scenarios**:

1. **Given** 活動已結束且存在作答，**When** 建立活動的老師開啟檢討畫面，**Then** 可依題號查看組別、答案與送出順位。
2. **Given** 活動已結束且某題無人作答，**When** 老師檢視完整紀錄，**Then** 該題明確標示無人作答且不虛構提交紀錄。
3. **Given** 非建立活動老師或未加入活動的學生嘗試查看老師紀錄，**When** 請求送達，**Then** 系統拒絕存取並提供清楚訊息。
4. **Given** 活動仍開放且某題已有人勝出，**When** 另一組首次提交有效答案，**Then** 該答案仍列入結束後的檢討紀錄並取得該題下一順位，但不改變原勝出組別。

### Edge Cases

- 學生在搶答尚未結束時要求完整結果，拒絕請求且不得在訊息、頁面或即時事件中洩漏答案或組別。
- 某題無人作答時，學生結果與老師檢討紀錄都須保留該題並清楚標示無人作答。
- 已結束活動不可在同一活動內重新開始；老師須建立新活動，新活動使用獨立作答紀錄。老師可繼續檢視舊結果；學生只可在其工作階段切換到新活動前檢視舊結果。
- 老師或學生重複載入結果時，資料與順位保持穩定；順位不可由頁面顯示順序重新推算。
- 權限不足或活動不存在時，回傳明確錯誤，不洩漏其他活動的結果。
- 同一組重複提交同一題時，僅第一筆有效提交列入檢討紀錄；後續重複提交不建立新順位或改變原紀錄。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 只在活動已結束後向學生提供完整題目結果；進行中請求須拒絕或回傳無資料的明確狀態，且不得包含組別或答案內容。
- **FR-002**: 系統 MUST 按活動已匯入的題號清單提供學生結果，包含成功組別及其有序答案；無人作答的題目 MUST 明確標示無人作答。
- **FR-003**: 建立活動的老師 MUST 能檢視活動結束後完整作答紀錄，至少包含題號、組別、答案及送出順位。
- **FR-004**: 老師完整作答紀錄 MUST 包含搶答進行期間每組每題第一筆有效提交，包括提交前該題已由其他組勝出的情況；無效、空白及同組重複提交不列入紀錄。已勝出的答案保持勝出，後續有效提交只作為檢討紀錄，不得覆寫勝出結果。
- **FR-005**: 系統 MUST 依每一題分別計算送出順位，從該題第一筆有效提交開始排序；順位依系統接收並記錄的先後決定，且結果重讀後保持一致。
- **FR-006**: 系統 MUST 驗證結果讀取者的角色及活動歸屬；學生不得在搶答結束前取得其他組別或完整作答紀錄。
- **FR-007**: 結果頁的題目、紀錄與順位 MUST 穩定一致；重新載入不得改變已保存的提交順序。
- **FR-008**: 老師檢討功能在本子功能中以結果檢視為範圍，不新增作答批改、分數或自由文字註記。
- **FR-009**: 已結束活動 MUST 不可在同一活動內重新開始；老師建立新活動時，舊活動結果保持不變並仍可由建立活動的老師檢視，新活動結果與舊活動隔離。學生只能在目前工作階段仍隸屬舊活動時檢視舊結果；加入新活動後不得再讀取舊活動結果。

### Key Entities *(include if data involved)*

- **活動結果集**: 一次已結束活動所對應的固定結果集合；結果歸屬於該活動，另建活動不會重設或覆寫舊結果。老師可持續檢視，學生檢視權限限於其目前活動組別關聯。
- **作答紀錄**: 題號、作答組別、有序答案及該題內穩定的送出順位；每組每題第一筆有效提交列入，即使不是勝出答案。
- **題目結果**: 題號、勝出組別及答案，或明確的無人作答狀態。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已結束活動的學生可看到與匯入題目數相同的結果列，每個題號恰好出現一次。
- **SC-002**: 活動進行中，學生檢視完整結果所取得的組別與答案欄位數為 0。
- **SC-003**: 老師完整紀錄中的每筆作答都顯示題號、組別、答案及順位；同一資料重複讀取時順位一致。
- **SC-004**: 無人作答的題目在學生與老師畫面均清楚標示，且不產生虛構答案紀錄。
- **SC-005**: 未授權角色取得完整老師作答紀錄的成功率為 0。

## Assumptions

- 沿用現有老師、學生、活動、組別與搶答結果；不新增帳號或角色。
- 每組每題最多保留第一筆有效提交；同題已有勝出組別後，其他組的第一筆有效提交仍記錄供檢討，但不改變勝出結果。
- 送出順位是題目內順位，不是跨題的全活動順位。
- 已結束活動不支援原活動重開；另建活動後舊結果繼續保存並與新活動結果分開。
- 學生工作階段只維持目前活動的組別關聯；加入新活動會移除該工作階段對舊活動結果的學生檢視資格。
- 學生結果頁按已匯入題號呈現，老師檢討頁可按題號查看紀錄及順位。
- 「進行檢討」表示老師查看並帶領討論，不包含儲存檢討筆記、判分或修改作答。
- 現有搶答資料可提供勝出答案；本功能需保存每題各組第一筆有效提交，以呈現完整檢討紀錄。
