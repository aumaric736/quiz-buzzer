# Feature Specification: 課堂搶答流程

**Feature Branch**: `003-buzzer-flow`  
**Created**: 2026-11-20  
**Status**: Draft  
**Input**: User description: 「老師可以開啟與結束搶答。搶答開始後，學生以組別為單位針對每一題送出答案。同一填空中最快送出的組別，其答案被選定為搶答成功的答案。老師可以即時檢視各題的作答狀況；學生在搶答結束前看不到其他組別的作答狀況。需處理幾乎同時提交、同組重複提交、空白答案、結束瞬間提交、題目已被搶答成功等情況。此功能需提供各題成功組別與答案的 provider，供 Guided Notes 子功能於結束後匯出；題號需符合已匯入 Guided Notes。**Clarifications**: 結束後學生可看完整結果；每組每題只接受第一次提交；有多個填空的題目由學生逐格輸入答案。**

## Clarifications

### Session 2026-11-20

- Q: 搶答結束後，學生是否可看各題成功組別與答案？ → A: 結束後可看完整結果；搶答進行中仍只能看自己的提交確認。
- Q: 同一組重複送同一題時如何處理？ → A: 每組每題只接受第一次提交，後續重複提交不會覆寫答案。
- Q: 多填空題如何輸入答案？ → A: 學生對每個填空分開輸入，並按填空順序提供答案片段。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 老師開啟與結束搶答 (Priority: P1)

老師在活動準備完成後開啟搶答，並在課堂活動結束時結束搶答。只有活動中匯入的 Guided Notes 題目可以作答；題號與順序沿用該活動的 Guided Notes 題目清單。

**Why this priority**: 搶答的開放與關閉狀態是所有學生提交及成功答案判定的依據。

**Independent Test**: 建立已有 Guided Notes 題目清單的活動，以老師角色開啟、結束搶答；驗證階段依序變更，其他角色或錯誤階段操作會被拒絕並顯示明確訊息。

**Acceptance Scenarios**:

1. **Given** 活動在準備中且已有 Guided Notes 題目，**When** 活動建立老師開啟搶答，**Then** 活動進入搶答進行中，學生可提交清單內題號的答案。
2. **Given** 活動正在搶答，**When** 活動建立老師結束搶答，**Then** 活動進入已結束，後續提交不再被接受，且最終答案結果可供查詢。
3. **Given** 活動沒有匯入 Guided Notes 題目，**When** 老師嘗試開啟搶答，**Then** 系統拒絕操作並指出需先匯入題目。
4. **Given** 學生或非活動建立老師嘗試開啟或結束搶答，**When** 請求送達，**Then** 系統拒絕操作且活動階段不變。
5. **Given** 老師已開啟搶答，**When** 老師尚未手動結束活動，**Then** 活動持續處於搶答進行中，不會因經過時間而自動結束。

---

### User Story 2 - 學生組別提交答案 (Priority: P1)

搶答進行中，學生以已加入活動的組別提交各題答案。每個填空欄位個別輸入；同一組每題只有第一次有效提交會被接收。每題第一個有效且成功保存的組別成為勝出組別，其有序答案成為該題成功答案。

**Why this priority**: 學生提交與唯一勝出答案是 Guided Notes 匯出及老師檢視結果的資料來源。

**Independent Test**: 開啟有多題與多組的活動，測試有效答案、空白答案、重複提交、已有人勝出的題目及接近結束時間的提交；確認每題只產生一個穩定勝出結果。

**Acceptance Scenarios**:

1. **Given** 活動正在搶答且題目尚無勝出組別，**When** 一組提交有效答案，**Then** 系統保存該組按填空順序排列的答案，並將該組選為該題勝出組別。
2. **Given** 同一題尚無有效答案且兩組幾乎同時提交，**When** 兩筆提交競爭保存，**Then** 只有第一筆成功保存的提交成為勝出答案，其他提交不覆蓋它。
3. **Given** 某組已提交某題答案，**When** 該組再次提交同一題，**Then** 系統以清楚的重複提交訊息拒絕第二次提交，既有答案不變。
4. **Given** 任一必填答案欄位空白或僅含空格，**When** 組別提交，**Then** 系統拒絕整筆提交且不改變題目狀態。
5. **Given** 某題已有勝出組別，**When** 其他組提交該題答案，**Then** 系統拒絕提交、不更改勝出結果，且不向學生透露勝出組別或其他組答案。
6. **Given** 活動結束與學生提交同時發生，**When** 系統處理兩個操作，**Then** 若答案先成功保存則納入最終結果；若結束先完成則拒絕答案，且只產生一種一致結果。

---

### User Story 3 - 老師即時監看及共用結果 (Priority: P1)

搶答期間，老師可即時查看各題的作答狀況、已提交組別及目前勝出答案。學生在活動結束前只收到自己提交的受理結果，不會看到其他組別的提交或勝出情形。活動結束後，學生可查看各題完整結果。

**Why this priority**: 老師需要在課堂中掌握進度，學生結果隔離則避免搶答中互相影響。

**Independent Test**: 以老師和多個學生組別同時連線，提交不同題目答案；驗證老師畫面即時更新、學生畫面不收到其他組別狀態；結束後確認學生可讀取最終結果。

**Acceptance Scenarios**:

1. **Given** 活動正在搶答且有組別提交答案，**When** 提交成功，**Then** 老師即時看到該題提交狀況及勝出答案更新。
2. **Given** 活動正在搶答，**When** 學生查看題目或收到更新，**Then** 只能看到自己的提交確認，不能取得其他組別的作答狀態、答案或勝出組別。
3. **Given** 活動已結束，**When** 學生或老師查看結果，**Then** 可依題號看到勝出組別與有序答案；無勝出組別的題目明確標示無人答對。

### Edge Cases

- 多組近乎同時提交同一題時，以第一筆成功保存的有效答案為準；後續請求不得覆寫。
- 同組同題的重複提交一律拒絕；不得把重試當成新的答案或改寫既有答案。
- 空字串、純空白答案、答案片段缺漏或片段數不符該題填空數時，拒絕整筆提交並指出欄位問題。
- 活動結束與答案提交競爭時，操作須以一致的先後次序生效；不得出現活動已結束但答案仍偶發接受的狀況。
- 題目已有勝出組別時，其他組的提交不得改變勝出答案；學生端的拒絕訊息不得暴露其他組資料。
- 準備中或已結束時提交答案均拒絕；未知活動、未知題號、未加入活動的組別及非學生角色也拒絕。
- 老師重複開啟或結束活動、非建立活動老師操作，須收到清楚錯誤且不得改變狀態。
- 活動沒有 Guided Notes 題目、題號重複或答案結果缺少題號時，不得啟動或回傳不完整的 provider 結果。
- 活動即時更新連線中斷或重連時，使用者重新載入後取得目前階段與可見範圍內的最新狀態；不可向學生補送搶答中其他組別資料。
- Guided Notes provider 只能在活動結束後提供完整題目集合的結果；未勝出的題目須明確回傳無勝出組別。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 允許活動建立老師在準備中開啟搶答，並允許該老師在搶答進行中結束搶答。
- **FR-002**: 系統 MUST 只允許具有已匯入 Guided Notes 題目清單的活動開始搶答；題號及順序 MUST 與該清單一致。
- **FR-003**: 系統 MUST 僅接受活動內已加入的學生組別，在搶答進行中對已匯入題號送出的答案。
- **FR-004**: 系統 MUST 驗證提交題號、組別、活動階段及每一答案片段；任一必填片段為空白時拒絕整筆提交且不留下部分狀態。
- **FR-005**: 每組每題 MUST 僅接受第一次有效提交；相同組別的後續提交 MUST 被拒絕且不得改寫先前提交。
- **FR-006**: 每題 MUST 最多有一個勝出組別；系統 MUST 以第一筆成功保存的有效提交作為勝出答案，並保留按填空順序排列的答案片段。
- **FR-007**: 當題目已有勝出答案時，系統 MUST 拒絕其他組別的後續答案，且不得改變既有成功答案。
- **FR-008**: 搶答結束操作與答案提交 MUST 以一致順序結算；結束成功後不得再接受答案。
- **FR-009**: 搶答期間，老師 MUST 能即時檢視每題提交進度、組別及勝出答案；資料更新須在 1 秒內呈現在已連線老師畫面。
- **FR-010**: 搶答進行中，學生 MUST 僅取得自己提交的受理狀態，不得讀取或收到其他組別的提交狀態、答案或勝出組別。
- **FR-011**: 搶答結束後，學生與老師 MUST 能依題號查看完整最終結果，包括勝出組別、有序答案及無勝出組別的題目。
- **FR-012**: 系統 MUST 提供 Guided Notes 子功能可在活動結束後取得的結果 provider；每個匯入題號都須有一筆結果，包含勝出組別與依序答案片段，或明確的無勝出狀態。
- **FR-013**: provider 回傳的題號 MUST 與該活動已匯入 Guided Notes 題號集合完全一致；缺漏、重複或未知題號不得作為完整結果回傳。
- **FR-014**: 活動階段、已接受提交、每題勝出組別及答案片段 MUST 持續保存；重整或即時連線恢復後，授權使用者可取得目前階段及其可見範圍內的最新狀態。
- **FR-015**: 所有老師操作、學生提交與結果讀取 MUST 驗證使用者角色、活動歸屬、組別身分及輸入內容，並回傳清楚且不洩漏其他組答案的錯誤訊息。
- **FR-016**: 系統 MUST 由老師手動結束搶答；在老師手動結束之前，活動 MUST 持續處於搶答進行中並接受有效答案，且不得因經過時間或倒數而自動結束。

### Key Entities *(include if feature involves data)*

- **活動搶答**: 某活動的準備、進行或結束階段，以及題目集合與相關權限。
- **活動題目**: 由 Guided Notes 匯入的題號；其題號是提交及答案 provider 的穩定識別。
- **學生組別**: 已加入該活動並代表組別提交答案的單位。
- **答案提交**: 一組對一題提交的一組有序答案片段及受理時間；每組每題最多一筆有效提交。
- **題目勝出結果**: 該題第一筆成功保存的提交所屬組別及有序答案片段，或無勝出組別的狀態。
- **即時作答狀況**: 老師可查看的題目提交進度與勝出結果；學生在活動結束前僅能查看自己的提交確認。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 老師在符合開始條件時，開啟或結束操作須於 2 秒內完成，且所有授權畫面須於階段改變後 1 秒內呈現新階段。這些時間是系統操作與同步延遲，不是搶答時長；搶答不會自動結束。
- **SC-002**: 每題至少 100 組同時有效提交的模擬中，恰有一筆被選為勝出答案，且勝出答案不可被後續請求改寫。
- **SC-003**: 每組每題重複提交及空白答案均有 100% 拒絕，且原有結果不變。
- **SC-004**: 搶答進行中，學生端可取得的其他組別作答紀錄數為 0；教師仍可在 1 秒內看到已提交及勝出狀態。
- **SC-005**: 活動結束後，provider 對每個匯入題號各回傳一筆結果；題號集合與 Guided Notes 完全相同，答案片段順序與學生填寫順序一致。
- **SC-006**: 結束與提交競爭測試中，系統 100% 遵循已保存答案與活動結束操作的先後順序，不產生結束後新接受答案。

## Assumptions

- 沿用現有本機老師／學生工作階段、活動及學生組別；本功能不新增帳號註冊或角色。
- 每個活動開始前，老師已匯入 Guided Notes，且學生組別已在準備階段加入活動。
- 題目答案不由本功能判定正確與否；每題第一筆符合格式且成功保存的答案即為搶答成功答案。
- 同組同題只接受第一次有效提交；需要修正答案時不可重新提交同一題。
- 多填空題的每個答案片段由學生在個別欄位輸入，並依填空順序回傳給 Guided Notes。
- 正式結束後，老師與學生都可查看完整題目結果；活動進行中只允許老師查看所有組別狀況。
- 答案結果保留於活動資料中，至少直到 Guided Notes 匯出功能取用完成；沿用專案既有活動資料保存週期。
- 幾乎同時提交的公平性依系統成功保存的先後次序決定；不依學生裝置時間戳排序。
- 搶答沒有倒數或自動結束；活動持續到老師手動結束為止。
- 即時同步只傳送符合角色可見範圍的活動狀態，不同步編輯 Google Sheets；Sheets 寫回由 Guided Notes 子功能負責。
